# 구조와 재사용 — 교체 가능한 전파 엔진

물리 정의는 [물리 모델](physics-model.md), 제품 범위는 [제품 설계](product-design.md), 조작과 문구는 [학생 화면과 언어](ux-language.md)에 둔다.

## 1. 책임과 의존 방향

TypeScript·Vite와 WebGL2·Canvas 2D·SVG·HTML을 사용한다. 물리 모델, 실행 장치, 화면 배치의 책임을 나눈다.

| 모듈 | 책임 |
| --- | --- |
| `model/types.ts`, `model/state.ts` | SI 단위의 공통 데이터, 목표 입력과 범위. DOM·엔진 구현에 의존하지 않음 |
| `runtime/clock.ts` | 단일 물리 시간과 재생·정지. 진동 위상을 계산하지 않음 |
| `runtime/frame-cadence.ts`, `field-quality.ts` | 처리 시간에 따른 해상도·15/30/60Hz 샘플링 시점. 물리 시계와 독립적 |
| `physics/engine.ts` | `WaveEngine`, `WaveFrame` 공개 계약 |
| `physics/retarded-engine.ts` | 현재 백엔드: 명령 적용, 발생 이력, 불변 프레임, 정상 상태 판정·필드 캐시 |
| `physics/history.ts` | 구간별 발생 위상·위치, 지연 시각 해, 이력 수명 관리 |

| `physics/sampling.ts` | 임의 공간점 샘플러를 경로·격자 샘플로 변환 |
| `physics/field-program.ts`, `retarded-field-program.ts` | 선택적 GPU 필드 계약, 현재 백엔드의 GLSL 수식·시간을 재기준화한 프레임 자료 |
| `rendering/webgl-field.ts` | 공통 GPU 자원·텍스처·필드 계산·색상·직접 표시. 파원 이력의 의미를 모름 |
| `rendering/field-surface.ts` | GPU/CPU 선택·복구, 필드 캐시, 성능 피드백과 배경 해상도 |
| `geometry/`, `visual/` | 좌표 변환, 공통 거리·변위 축척, 파형·점·막대·선 |

| `views/` | 전달받은 프레임 데이터와 샘플을 그림. 지연 시각·이력·격자 해법을 모름 |
| `ui/` | 접근 가능한 조작, 미리보기·확정·취소 이벤트와 학생 문구 |
| `app/main.ts` | 백엔드 선택 한 곳, 목표·미리보기·보기 상태, 시계와 엔진 및 뷰 연결 |

`views`와 `ui`는 `retarded-engine`, `history`, `source-motion`을 직접 가져오지 않는다. 엔진은 DOM, requestAnimationFrame, performance.now 또는 UI 문구를 사용하지 않는다.

## 2. 공개 엔진 계약

```ts
interface WaveEngine {
  advanceTo(timeSeconds: number): void;
  setWavelength(wavelength: number): void;
  setSourceTargets(positions: SourcePair<Vec2>): void;
  read(probe: Vec2, fieldBounds?: FieldBounds, options?: Readonly<{ equilibriumSources: SourcePair<Vec2> }>): WaveFrame;
  settle(): void;
  reset(model: ModelState): void;
}
interface WaveFrame {
  readonly snapshot: PhysicsSnapshot;
  readonly fieldBounds: FieldBounds;
  samplePoint(point: Vec2): ProbeSample;
  samplePaths(): SourcePair<PathSample>;
  sampleField(columns: number, rows: number, mode: FieldMode): FieldGrid;
  fieldProgram?(): FieldProgram | undefined;
}
```

- `advanceTo`는 단조 증가하는 물리 시간만 받는다. 명령은 마지막으로 진행한 시각에 적용한다. P 변경은 `read`의 샘플 위치만 바꾼다.
- `read`는 시간이나 이력을 진행시키지 않는다. 반환한 프레임은 이후 명령·재생·초기화·이력 삭제에도 같은 결과를 제공한다.
- `settle`은 현재 시각·발생 위상을 보존하고 파원을 목표 위치에 즉시 정착시킨다. 위치·위상 이력은 각각 한 기준 기록으로 정리하고 진행 중인 이동을 종료한다. 앱은 `instant` 옵션 선택과 이 옵션에서의 파장·간격 확정에 호출한다. 따라서 미완료 이동을 백그라운드에서 적분하지 않으며 파동 모습으로 돌아가도 동일한 최종 상태를 유지한다.
- `equilibriumSources`를 전달하면 현재 파장·현재 발생 위상과 지정된 최종 위치의 정상 상태 프레임을 반환한다. 앱은 `instant` 옵션의 미확정 드래그에만 이 옵션을 사용하고, 확정 상태는 일반 `read`로 읽는다. 현재 백엔드는 미리보기 프레임만의 고정 위치·일정 진동수 이력을 만들어 기존 CPU·GPU 샘플링을 공유한다. 미리보기는 실제 시각이나 이력을 바꾸지 않아 취소가 가능하다.
- 기준 장치 크기인 `model.bounds`와 표시할 `fieldBounds`(원점 x·y와 폭·높이)는 별개다. P는 기준 장치 바깥에서도 샘플링할 수 있다. 프레임의 CPU 격자와 GPU 필드는 같은 표시 사각형을 사용한다. 생략하면 기준 장치 영역을 샘플링한다. 정상 상태와 정지 위치 최적화는 표시 영역과 기준 장치 영역 전체에 변화가 도달했을 때만 사용한다.
- `geometry/probe-region.ts`가 P의 화면 제약을 소유한다. 비교를 펼친 관찰 창에서 16px를 뺀 사각형과, 최대 파원 간격의 양 끝을 중심으로 비교 가능한 경로 길이를 반지름으로 한 두 원판의 교집합이다. 입력은 이 볼록 영역의 가장 가까운 점으로 제한하고, 경계 표시는 같은 영역에서 생성한다. 중간·과거 파원 위치도 이 두 극점 사이에 있으므로 전체 이동 중 경로 길이를 보장한다. 앱은 화면 크기 변경 시 영역을 갱신하고 필요할 때 P를 보정한다. 물리 모델은 화면 제약 없이 유한한 좌표를 받는다.
- 엔진 생성 시 최대 표시 범위 `fieldEnvelope`를 전달해 화면 크기 변경 전에 필요한 이력을 미리 보존한다. 앱의 `sceneFieldEnvelope`는 기본 가로 286~1000px·세로 170~360px 및 가로 전용 전체 폭 526~1000px·높이 180~360px의 접힌/펼친 카메라 극값에서 계산한다. 이 범위를 바꾸는 레이아웃 변경은 예약 범위도 함께 조정해야 한다. 예약 범위 밖의 샘플링은 오류로 처리해 잘못된 과거 파동을 그리지 않는다.
- 스냅샷의 `model.sources`는 기본 읽기에서 실제 위치, 최종해 읽기에서는 요청한 최종 위치다. `probe.origins`는 표시하는 공간 선분의 시작점이며 현재 백엔드에서는 그 프레임에서 P에 도착한 성분의 발생 위치다.
- `ProbeSample`은 두 거리·시작점·순간 변위·합과 정상 상태의 진폭·위상차·판정을 제공한다. 과도 상태의 진폭·위상차는 `null`이다.
- `snapshot.steady`는 공간 전체가 현재의 정지한 파원 조건으로 채워졌는지를 나타낸다. P의 국소 판정과 구별한다. `moving`은 미완료 목표가 있는 상태를 포함한다.
- `sampleField`의 `amplitude`는 도착 위상 포락선이다. 정상 상태에서 합성 진폭과 같고 과도 상태에서도 샘플링할 수 있다. 정상 상태 판정·수치 유보와 구별한다. 동적 무늬의 캐시에는 시각과 정상 상태 여부를 포함하고 자동 품질 조절을 적용한다.
- 현재 백엔드의 정규화는 진폭 합 `2A` 기준이다. 표시할 물리량과 변위 범위가 바뀌는 새 백엔드는 해당 데이터 계약까지 개정한다.
- `fieldProgram`은 같은 프레임의 선택적 GPU 표현이다. GLSL ES 3.00의 `fieldValue(point, amplitude)` 함수, RGBA32F 입력 텍스처, 숫자 uniform만 전달한다. GL 컨텍스트·텍스처 핸들은 포함하지 않는다. 함수의 좌표·정규화는 CPU 샘플과 같다. 미지원 백엔드는 이 함수를 생략할 수 있다.
- GPU 전용 수식과 이력 패킹은 물리 백엔드에 둔다. 프레젠터는 커널 키·입력 자료만 다루며 이력을 역해석하지 않는다. 입력 자료는 프레임 소유로 읽기 전용이며, 정지 중 재그리기에 재사용한다.

### 상세 옵션

`ViewState.changeMode`는 `propagate | instant`이며 기본값은 `propagate`다. 앱이 정책을 엔진 명령으로 번역하고 뷰는 같은 프레임을 소비한다. `ui/floating-panel.ts`는 색상·옵션 패널과 설명 버블의 화면 경계 배치를 공유한다. `ui/detail-options.ts`는 패널·설명 버블의 위치와 열기/닫기·키보드·터치만 담당한다. 옵션은 셸의 그룹에 추가하고 동작은 앱에 연결한다. 닫기·바깥 누르기·Escape로 닫고, 화면 회전 시 위치를 다시 제한한다. 새 엔진은 포락선 표시량과 즉시 정착 계약을 명시적으로 구현해야 한다.

## 3. 목표·미리보기·실제 상태

앱의 `ModelState.sources`는 입력으로 확정한 목표 위치다. 포인터 이동 중 `previewSeparation`은 표시 상태에만 존재한다. 손을 떼면 목표를 확정하고 엔진에 전달한다. 엔진 프레임의 파원 위치가 실제 위치의 유일한 출처다.

히트 테스트는 실제 파원 위치를 사용한다. 키보드 증분과 간격 조절기의 값은 목표 간격을 사용하므로 이동 중 연속 입력도 누적된다. 점선 손잡이는 미리보기 또는 이동 중 목표를 나타낸다. 과거 발생 위치는 별도의 작은 속빈점이다.

입력 처리 순서:

1. 공통 시계를 현재까지 진행하고 엔진도 같은 시각까지 진행한다.
2. 목표 입력을 범위 안으로 정리한다.
3. 파장·파원 목표 명령을 엔진에 전달한다.
4. 같은 시각의 프레임을 읽어 결과와 조작부를 갱신한다.

엔진은 실제 경과 시간을 따라 진행하고, 샘플링 시점에 하나의 `WaveFrame`에서 필드·경로·P를 함께 읽는다. 샘플링 사이에는 같은 프레임을 보관해 모든 물리 표시의 시각을 일치시킨다. 입력 미리보기와 펼치기 배치는 화면 주사율에 맞춰 갱신할 수 있다. 학생 문구는 앱/UI 계층에서 데이터에 따라 결정한다. 사용자가 선택한 재생 상태와 보기 상태는 초기화·전환에서도 유지한다.

## 4. 물리 샘플과 화면 배치

거리 축척은 허용된 전체 파원 범위와 화면 크기로 정한다. 실제 위치, 목표 위치, 과거 발생 위치, P, 경로 펼치기에 같은 변환을 적용한다. 표시 중인 두 선분을 시작점 정렬로 펼치고 길이는 보존한다. 창 전체를 역변환한 사각형까지 파동을 샘플링해 레터박스를 없앤다. 이 렌더링 방식 자체는 창 크기·최소 높이·스크롤 정책·조작 범위를 바꾸지 않는다.

가로 전용 배치는 `landscapeColumns`가 관찰·비교 폭을 정한다. `createSceneTransform`은 두 폭 중 제한되는 쪽으로 공통 축척을 예약한다. 펼치기 동안 관찰 카메라 폭은 줄지만 축척은 고정되고, 비교 뷰는 `offsetX`로 오른쪽 도착 위치를 받는다. 화면 회전 시 크기와 위치만 재계산하며 엔진·재생 상태는 유지한다. 진행 중 포인터 캡처는 취소해 회전 전 좌표의 드래그를 적용하지 않는다.

파형 곡선은 해당 선분을 따른 현재 변위를 샘플링한다. 오른쪽 두 점은 경로 끝과 같은 값, 세 번째 점은 그 합이다. 수평 점선은 같은 값을 대응시키는 보조선이며 전파 경로가 아니다. 과도 상태의 거리·파장 해석은 물리 문서를 따른다.

`ViewState.pathWaves`는 접힌 공간 경로의 파형 표시만 제어한다. 같은 비교 뷰를 펼침 진행도 0으로 렌더링하므로 공간 미리보기와 펼친 파형의 샘플·축척은 같다. 비교 영역의 높이는 펼침 진행도를 따르되 SVG 좌표계는 최종 높이로 고정하고 컨테이너에서 잘라내므로 파형이 늘어나지 않는다. 보조 표시 그룹은 파형 도착 후 불투명도를 높이고, 접을 때는 불투명도를 먼저 낮춘 뒤 파형을 이동한다. 정지 상태에서도 보기 전환 애니메이션은 끝까지 진행하며 물리 시간은 바꾸지 않는다. `visual/wavelength-ruler.ts`는 한 파장 기준 막대와 고정된 중앙 눈금자의 동일한 λ·λ/2 눈금 모양, 선택 구간의 음영을 관리한다. 중앙 눈금자의 원점은 짧은 경로 끝인 `commonX`, 끝은 `pointX`, 높이는 두 `rowZeros`의 평균이다. 반파장 눈금도 `commonX`에서 시작하므로 경로차를 직접 읽을 수 있다. 경로차 음영은 두 경로 끝의 x 좌표로 결정한다. 짧은 쪽 막대는 같은 거리의 두 파형 값을 잇고, 긴 쪽 막대는 긴 경로 끝과 다른 행의 기존 수평 끝값 연결선을 잇는다.

색상 프리셋은 앱의 표시 상태다. Canvas와 색상바는 같은 색상표를 사용하며 필드 렌더러는 프리셋 변경 시 색 픽셀 캐시를 갱신한다. 정지 중이나 고정된 진폭 보기에서도 즉시 다시 칠한다. 엔진 프레임·시간·파원 색상·비교부 색상은 프리셋과 독립적이다.

## 5. 현재 백엔드의 성능과 수명

- GPU 경로는 정상·과도 상태 모두 60Hz를 목표로 한다. CPU 대체 경로는 정상 상태 60Hz·과도 상태 30Hz로 시작한다. 부하가 지속되면 배경 해상도를 낮추고, 필요하면 GPU 30Hz 또는 CPU 과도 상태 15Hz까지 조절한다. `퍼져 나가기`의 연속 입력은 두 보기 모두 재생 중 샘플링 상한을 유지한다. `즉시 최종 상태`의 설정·미리보기 변경은 다음 화면 프레임에서 최종해를 즉시 다시 그린다. 물리 시간·진동수·이동 적분 간격은 바꾸지 않는다.
- 배경 해상도는 화면상 파동 영역 크기·DPR·품질 단계로 정한다. GPU 가로 1024, CPU 640 샘플 및 DPR 2를 상한으로 두고 최소 160 열을 유지한다. 기본 GPU 밀도는 CSS 픽셀당 1 샘플이며 여유가 지속되면 DPR 범위까지 높인다. 정지 중과 GPU의 정적 진폭 보기에서는 허용된 높은 해상도로 그린다. SVG 글자·조작점·비교 길이는 품질 단계와 무관하다.
- 필드 CPU 처리 시간, 전체 프레임 CPU 처리 시간, 표시 간격의 이동 평균과 선택적 비동기 GPU 시간 쿼리를 사용한다. 준비 구간을 제외하고 과부하 8회에 하향, 여유 120회에 상향한다. CPU 경로 그리기가 병목이면 배경을 흐리게 만들기보다 갱신 빈도를 조절한다. 긴 페이지 중단 간격은 성능 저하로 해석하지 않는다.
- GPU는 이력에서 각 위치의 변위를 계산하고 RGBA8 필드 텍스처에 색칠한 뒤 화면으로 직접 확대 표시한다. 앱 실행 경로에는 `readPixels`, `finish`, GPU 필드의 CPU 복사가 없다. CPU 기준 계산은 P·경로 비교·대체 렌더링에 사용한다.
- RGBA32F 입력 샘플링과 RGBA8 출력은 WebGL2 기본 기능을 사용하며 부동소수점 렌더 타깃 확장을 요구하지 않는다. 시간은 현재 시각에 대한 상대값, 위상은 주기 내 값으로 변환해 장시간 실행의 Float32 정밀도 저하를 줄인다. 현재 이력 텍스처 상한은 4096 기록이며 초과 시 CPU 경로를 쓴다.
- 초기 GPU 미지원·셰이더 실패·자원 손실은 같은 물리 프레임의 CPU 화면으로 전환한다. 컨텍스트가 복구되면 자원을 다시 만들고 GPU로 복귀한다. 한 세션에서 자원 손실이 반복되면 CPU에 머문다. 애니메이션 상태나 실험 이력은 초기화하지 않는다.
- 화면 캔버스는 정지 상태와 캡처를 위해 drawing buffer를 보존한다. 안티앨리어싱·깊이·스텐실 버퍼를 사용하지 않으며 출력 크기와 필드 텍스처에 상한을 둔다. 프로그램·텍스처·시간 쿼리·프레임버퍼·이벤트는 해당 프레젠터 수명에 맞춰 해제한다.
- 정지·정상 상태에서는 필드의 공간 사인·코사인 계수를 캐시하고 시간 성분만 갱신한다. 고정 진폭 무늬는 매 프레임 다시 칠하지 않는다.
- 파장만 변경해 위치 이력의 영향이 없는 경우에는 파원별 격자 전파 시간을 캐시하고 발생 위상만 다시 읽는다. 캐시의 기준은 격자 크기·영역·실제 파원 위치·파속이며 파장과 P는 제외한다.
- 파원 이동 중 또는 이동의 영향이 공간에 남은 동안에는 과거 위치로부터 발생 시각을 풀어 필드를 샘플링한다. 파원이 멈춘 순간에 정지 위치 캐시로 전환하지 않는다. 화면 픽셀과 물리 이력의 해상도는 서로 독립적이다.
- 이력은 예약된 최대 표시 범위까지의 전파 시간과 직전 기준 기록을 유지한다. GPU 시간 재기준화도 같은 보관 범위를 따른다. `WaveFrame`이 참조하는 기록은 불변이며 앱은 최신 프레임만 보관한다.
- 이벤트, 관측자, 애니메이션 프레임의 수명은 앱이 관리한다. 숨겨진 페이지에서는 물리 시계를 멈추어 복귀 시 시간이 갑자기 진행하지 않게 한다.

## 6. PhET 같은 격자 엔진으로의 교체

미래 백엔드는 같은 명령과 샘플링 인터페이스를 구현하고 앱 조립부의 생성 함수만 교체한다. 이력 배열이나 지연 시각은 공개 계약이 아니므로 유지할 필요가 없다. 공통 시간과 파원 목표 이동은 재사용할 수 있다.

격자 엔진에서 특히 확인할 사항:

- 파원별 기여를 구분해 반환해야 한다. 합성 격자 하나만 유지하면 성분·합 비교에 필요한 두 성분을 자동으로 분리할 수 없다.
- 경로 샘플과 P는 같은 프레임·보간 규칙을 사용해야 한다.
- GPU 격자 백엔드도 필드 프로그램 계약을 구현하거나 별도의 GPU 자원 전달 계약을 확장할 수 있다. 현재 계약은 CPU 소유 입력 텍스처를 전달하는 형태이며 GPU 안에서 유지되는 시간 적분 격자를 지원 완료로 간주하지 않는다.
- 발생 위치를 추적하지 않는다면 현재 파원에서 P로의 공간 단면으로 정의하고, 실제 발생 경로처럼 설명하지 않는다. 필요 시 경로 의미를 나타내는 명시적인 계약을 추가한다.
- 정상 상태 판정과 진폭 추정은 백엔드가 책임진다. 신뢰할 수 없으면 수치를 제공하지 않는다.
- 진폭 감소·반사·격자 오차를 도입하면 기존의 등진폭 상쇄·표시 범위 가정을 함께 바꾼다.

현재는 교체 지점을 마련한 것이며 격자 백엔드나 런타임 엔진 선택 UI를 구현한 것은 아니다. 추측성 플러그인 등록부·이벤트 버스·서버는 추가하지 않는다.

### P 입력 보조 경계

`geometry/probe-detent.ts`는 드래그별 통과·걸림·해제·재진입 상태와 수치 등위선 투영만 관리한다. 앱은 정상 상태 `WaveFrame.samplePoint().phaseDifference`를 공급하고, 위상차의 π 정수 배를 간섭선으로 사용한다. 입력 모듈은 파원 거리 공식이나 현재 엔진 구현을 알지 않는다. 엔진이 정상 위상차를 제공하지 않으면 입력 보조를 생략한다. 허용 영역 검사와 화면 축척은 기존 배치 모듈의 값을 공유한다. 정밀 보조는 입력 이벤트에서만 계산하며 물리 시계·파원 조건·렌더링에는 영향을 주지 않는다.
