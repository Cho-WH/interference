# 구조와 재사용

물리량·계산 의미는 [물리 모델](physics-model.md), 조작과 화면 규격은 [학생 화면과 언어](ux-language.md), 제품 범위는 [제품 설계](product-design.md)에 둔다. 이 문서는 모듈 간 책임·데이터·수명 계약을 정의한다. 함수 시그니처는 링크한 TypeScript 선언을 기준으로 한다.

## 1. 책임과 의존 방향

| 계층 | 소유하는 책임 | 의존하지 않는 것 |
| --- | --- | --- |
| `model/` | SI 단위 데이터, 기본 조건, `LIMITS`, 입력 정규화 | DOM, 시계, 물리 백엔드 |
| `physics/engine.ts` | `WaveEngine`·`WaveFrame` 공개 계약 | 특정 해법, 렌더링 장치 |
| `physics/retarded-engine.ts`, `history.ts`, `source-motion.ts` | 명령·이력·지연 시각·이동·정상 상태·캐시 식별 | DOM, 벽시계, 학생 문구 |
| `physics/sampling.ts` | 백엔드가 전달한 점 샘플러와 간격으로 경로·격자 생성 | 속력 상한, 파장 입력 범위, 지연 해법 |
| `physics/field-program.ts`, `retarded-field-program.ts` | 선택적 GPU 계약, 백엔드 수식과 데이터 패킹 | GL 자원·팔레트 |
| `runtime/` | 물리 시계, 샘플링 빈도·품질 정책, 별도의 화면 전환 진행도 | DOM·학생 문구·백엔드 구현 |
| `geometry/` | 좌표·공통 축척, P 영역, 손잡이 위치·히트 테스트, 드래그 걸림 | DOM, 지연 해법 |
| `visual/` | 공통 SVG 요소·눈금, 색상표·그라데이션 | 엔진 명령, 입력 상태 |
| `rendering/` | GPU/CPU 표시·복구, 색칠·출력 캐시, 처리 시간 피드백 | 파원 이력과 정상해 수식 |
| `views/` | 전달된 프레임·샘플을 필드와 경로로 그림 | 엔진 명령, 이력·지연 시각 계산 |
| `ui/` | 정적 셸·문구·수치 표시, 접근성, 입력 콜백, 팝업 | 물리 백엔드 구현 |
| `app/experiment-controller.ts` | 공통 엔진·시계, 입력 정규화·권한, 명령 적용·프레임 읽기 | DOM, 수업 위치, 연출 |
| `app/main.ts` | 일반 모드 보기·미리보기 상태, P 영역 정책, 프레임 배포·자원 수명 | 개별 표시 문구와 전환 보간식 |
| `app/teacher.ts` | 수업 제어기·실험·무대 연결, 공통 프레임 배포·자원 수명 | 물리 계산, 경로 그리기·전환 보간식 |
| `lesson/` | 수업 데이터, 단계 위치와 출발 단계의 명시적 시계 의도 | DOM, 엔진·애니메이션 실행 |
| `presentation/` | 고정 공간 카메라, 경로 배치·공통 축척, 연출 시간과 레이어 조합 | 엔진 명령, 수업 위치 결정 |
| `app/bootstrap.ts`, `session.ts` | 실행·예외 경계, 부분 초기화 정리, 세션 진단 기록 | 물리 계산·오류 화면 마크업 |

의존 방향은 `app → UI/뷰/렌더링/공통 계약`이다. `views`·`ui`·`rendering`은 `retarded-engine`·`history`·`source-motion`을 직접 가져오지 않는다. CPU와 GLSL은 실행 언어가 달라 각각 구현하되 픽셀 일치 검사로 같은 물리량을 검증한다. 이를 억지로 하나의 코드 생성 계층으로 합치지 않는다.

## 2. 엔진 경계

공개 선언: [engine.ts](../src/physics/engine.ts), 공통 데이터: [types.ts](../src/model/types.ts).

| 호출·데이터 | 계약 |
| --- | --- |
| `advanceTo(t)` | 초 단위의 유한한 단조 증가 시각. 명령은 마지막 진행 시각에 적용한다. 물리 시간의 유일한 출처는 앱의 공통 시계다. |
| `setWavelength`, `setSourceTargets` | 새 발생 조건·이동 목표를 설정한다. 파장은 공통 입력 범위로 정규화하고 파원 목표는 기준 장치 영역 안의 유한한 좌표여야 한다. |
| `read(P, fieldBounds?, options?)` | 시간·이력을 진행하지 않고 한 시각의 프레임을 반환한다. P는 기준 장치 밖도 가능하지만 예약된 샘플링 영역 안이어야 한다. 경로 샘플을 사용할 때에는 P를 요청한 표시 영역 안에 둔다. |
| `equilibriumSources` | 현재 시각·발생 위상과 지정 위치의 최종해를 별도 프레임으로 읽는다. 미리보기를 취소해도 실제 이력은 변하지 않는다. |
| `settle()` | 현재 시각·발생 위상을 유지하며 목표 위치에 정착한다. 과거 전파·미완료 이동을 제거한다. |
| `reset(model)` | 물리 시간 0, 입력 조건의 정상 상태로 복원한다. 재생·팔레트·옵션 유지 정책은 앱이 소유한다. |
| `snapshot.model.sources` | 일반 프레임에서는 실제 위치, 최종해 미리보기에서는 요청 위치다. 앱이 가진 목표 위치와 구별한다. |
| `probe.origins` | 표시하는 공간 단면의 시작점. 현재 백엔드는 P에 도착한 성분의 과거 발생 위치를 사용한다. |
| `probe.phaseDifference/resultantAmplitude` | P가 정상 상태일 때만 제공한다. 변화 중에는 `null`, 판정은 `transient`다. |
| `snapshot.steady/moving` | `steady`는 표시 영역과 기준 장치 전체에 최신 조건이 도달했는지, `moving`은 미완료 목표가 있는지를 나타낸다. P의 국소 판정과 다르다. |

프레임은 이후 명령·진행·이력 정리·초기화로 바뀌지 않는다. CPU 격자는 호출마다 별도 배열을 반환하며, GPU 패킷의 형식화 배열은 프레임 소유의 읽기 전용 자료로 취급한다. `Readonly`가 형식화 배열의 런타임 변경까지 막는다는 뜻은 아니다.

검증은 입력·공개 엔진·장치 경계에서 수행한다. 공통 정규화 함수 호출 전에 같은 유한값 검사를 반복하지 않는다. GPU 크기 제한은 자원 생성·크기 변경 때 검사한다. 시간 역행·이력 범위·장치 오류 검사와 수치 해의 발산/퇴화 방지는 유지한다. 모델과 엔진은 독립적으로 호출할 수 있으므로 각 공개 진입점의 입력 정규화는 공유하되 생략하지 않는다.

### 샘플과 캐시

- `samplePoint(P)`는 SI 단위 값이다. `samplePaths()`는 각 시작점에서 P까지 거리 오름차순 배열이며 0·끝·두 경로의 공통 거리를 정확히 포함한다. 끝 변위는 스냅샷의 P 성분과 같다. 백엔드가 `createWaveFrame`에 최대 샘플 간격을 지정한다.
- `sampleField(columns, rows, mode)`는 행 우선 격자다. 왼쪽 위가 `fieldBounds.x/y`, 양 끝을 포함하고 한 행/열이면 중앙을 샘플링한다. 크기는 양의 정수다. 현재 표시 계약은 변위 `[-1,1]`, 포락선 `[0,1]`이며 정규화 기준은 진폭 합이다.
- 선택적 `fieldCacheKey(mode)`는 불투명한 필드 식별값이다. 같은 키·영역·모드·격자 크기는 같은 값을 보장한다. 키가 없으면 렌더러는 동일 프레임 객체에서만 재사용한다. 해상도·팔레트·표시 크기는 렌더러 책임이다.
- 현재 백엔드는 명령 세대·실제/미리보기 조건·정상 여부로 키를 만들고 동적 필드에는 시간을 포함한다. P만 변경하거나 정상 진폭 보기에서 시간만 진행하면 공간값은 재사용 가능하다. 보관된 프레임의 키도 바뀌지 않는다.
- `amplitude`의 정확한 의미와 과도 상태의 한계는 [물리 모델 §4](physics-model.md#4-정상-상태와-전환-상태)를 따른다.

### 선택적 GPU 경계

[FieldProgram](../src/physics/field-program.ts)은 GLSL ES 3.00 `fieldValue(point, amplitude)` 함수, RGBA32F 입력 텍스처 자료, 숫자 uniform을 전달한다. 좌표·정규화는 CPU와 같다. `key`는 셰이더 프로그램 식별이며 `fieldCacheKey`와 역할이 다르다. GL 컨텍스트·텍스처 핸들은 전달하지 않는다. GPU 패킷을 제공하지 않아도 CPU 계약만으로 동작해야 한다.

백엔드는 수식·이력 패킹·상대 시간/위상 재기준화를 소유한다. 렌더러는 자원 생성·출력 텍스처·팔레트·복구를 소유하며 이력을 역해석하지 않는다. GPU 필드의 CPU 복사는 실제 표시 경로에 없고 테스트에서만 픽셀을 읽는다.

## 3. 입력·상태·표현 경계

`visual/wavelength-ruler.ts`는 λ·λ/2 눈금, 경로차 음영, 정지한 점선 기준 사인파를 함께 그린다. 일반·교사 비교 뷰는 같은 요소에 화면상의 파장 길이를 전달한다. 기준 사인파는 측정 보조 도형이며 물리 엔진의 파형이나 시계를 복제하지 않는다.

- `visual/point-markers.ts`는 파원 번호 원과 고정 관측점 P의 모양을 관리한다. 공간 손잡이, 교사 경로의 시작점, 동작 감소의 대응 도식이 이를 재사용한다. 입력 손잡이의 선택 영역·초점 표시는 `views/field.ts`에 남는다. 교사 공간에서 경로 시작점과 현재 파원이 겹치면 경로가 원과 번호를 한 번만 그리며, 공간 손잡이는 입력을 계속 받는다. 과거 발생 위치와 현재 파원이 다르면 두 위치를 별도로 표시한다.
- 교사 조작부의 파장·간격 범위는 `model/state.ts`의 `LIMITS`, 재생 배속은 `model/playback.ts`의 `PLAYBACK_RATES`, 거리 문구는 `ui/copy.ts`의 형식 함수를 사용한다. 장면 배치·진행 버튼은 교사 수업의 책임이며 공통 물리 조작과 분리한다.

입력 흐름은 `공통 시계 진행 → 입력 정규화 → 엔진 명령 → 같은 시각의 프레임 읽기 → 표시`다.

- 앱의 `model.sources`는 확정 목표, `previewSeparation`은 미확정 표시값, 프레임의 파원 위치는 실제 표시 위치다. 프리뷰와 확정은 `normalizeParameter`를 공유한다. 셸의 슬라이더 범위·초기값도 모델에서 가져온다.
- `propagate`에서는 새 조건이 전파된다. `instant`에서는 옵션 선택·조건 확정 시 `settle`, 미확정 위치에는 `equilibriumSources`를 사용한다. 보기 전환 자체는 정착 명령이 아니다.
- 입력 콜백은 P 이동·간격 미리보기/확정/취소·접근성 알림을 전달한다. 물리 계산이나 화면 문구를 만들지 않는다. 포인터는 실제 파원 위치를 선택하고 키보드 증분은 목표 간격에 누적한다.
- `geometry/field-handles.ts`의 손잡이 중심·선택 반경·가까운 파원의 간격 손잡이를 표시와 히트 테스트가 공유한다. 색은 밝은 필드 위와 밝은 패널 위에서 서로 다른 명도를 사용하되 파원별 색 계열을 유지한다.
- `geometry/probe-detent.ts`는 드래그 통과·걸림·해제 상태와 등위선 투영만 소유한다. `app/probe-guide.ts`가 공통 프레임의 정상 여부와 위상차 샘플러를 연결하고, 각 앱은 허용 영역·축척·예측 단계의 사용 정책을 제공한다. 위상차가 없거나 과도 상태이면 생략한다. 효과 규격은 UX 문서에 둔다.
- `ui/observation-panel.ts`는 입력 상태·표시 프레임을 받아 조절값·문구·접근성 속성만 갱신한다. `ui/floating-panel.ts`는 팝업의 배치·바깥 누름·초점 이탈·Escape·수명 정리를 공유한다. 선택 항목 탐색과 설명 버블은 각 기능이 소유하며, 설명 버블은 Escape를 먼저 소비한다.

## 4. 시간·화면 배치 경계

`clock`은 물리 초, `frame-cadence`는 샘플 시점, `comparison-transition`은 화면 ms를 다룬다. 화면 전환은 정지 중에도 진행하지만 물리 시간은 바꾸지 않는다. 앱은 샘플링 사이에 같은 프레임과 경로 샘플을 유지한다. 필드·두 경로·P·합성점은 그 프레임을 함께 소비한다.

재생 배속 단계는 `model/playback.ts`, 선택은 앱의 보기 상태가 소유한다. `clock.setRate(rate, now)`는 변경 직전까지 기존 배속으로 진행하고 이후 경과 시간에 새 배속을 곱한다. 배속은 유한한 양수이며 정지·초기화 후에도 유지한다. 앱은 반환 시각까지 엔진을 진행한다. 물리적 파동 속력·파장·이동 속력 제한, 화면 샘플링 빈도와 펼치기 애니메이션 시간은 변경하지 않는다.

`geometry/layout.ts`가 공간·비교의 공통 px/m를 결정한다. `probe-region.ts`는 최종 펼침 카메라와 비교 가능한 경로 길이로 P 영역을 정한다. 펼치기·P 이동·파장 변경은 축척을 바꾸지 않고, 화면 크기 변경 시에만 함께 재계산한다. 시각화의 길이·끝값 계약은 [UX 문서](ux-language.md#3-경로-펼치기와-진동-비교)에 둔다.

현재 레이아웃의 최대 표시 영역은 `sceneFieldEnvelope`로 엔진 생성 시 예약한다. CSS의 최소/최대 창 크기·가로 배치가 바뀌면 이 예약 범위와 영역 검증도 함께 바꿔야 한다. `model.bounds`는 장치 범위, `frame.fieldBounds`는 실제 카메라 범위다. 엔진은 예약 범위를 벗어난 필드 요청을 거부한다.

## 5. 자원·성능 수명

- `field-surface`는 프레임을 보존한 채 GPU/CPU를 선택한다. 셰이더 실패·컨텍스트 손실 시 즉시 CPU로 표시하고 복구 시 자원을 다시 만든다. 반복 손실 시 해당 세션은 CPU를 사용한다.
- `field-quality`는 필드 CPU 시간·나머지 프레임 시간·표시 간격·선택적 GPU 시간으로 품질을 조정한다. GPU는 60Hz, CPU 과도 상태는 30Hz에서 시작하며 지속 부하에서 30/15Hz까지 낮춘다. 해상도와 빈도만 바꾸고 물리 시간을 줄이지 않는다.
- 필드 해상도 상한은 GPU 1024열·CPU 640열·DPR 2, 하한은 160열이다. 정지 중과 GPU 정상 진폭 보기에서는 허용된 높은 해상도를 사용한다. SVG와 글자는 영향을 받지 않는다. 정확한 품질 단계·임계치는 `runtime/field-quality.ts`를 따른다.
- 현재 CPU 백엔드는 정상 상태의 공간 사인·코사인 계수를 캐시한다. 위치 영향이 사라진 과도 상태에는 전파 거리를 재사용한다. 이동 영향이 남아 있으면 지연 시각을 푼다. 이는 엔진 내부 최적화이며 공개 계약이 아니다.
- 이력은 예약 영역에 필요한 전파 시간과 직전 기준 기록을 보존한다. GPU 입력 상한 초과 시 CPU로 전환한다. 프레임이 참조하는 기록은 바꾸지 않는다.
- 앱은 이벤트·관측자·RAF·타이머를, 각 UI/렌더링 객체는 자신이 만든 이벤트·DOM/GL 자원을 해제한다. 숨김 페이지에서는 물리 시계를 멈춘다. Vite 교체 시 같은 정리 경로를 사용한다.

### 오류와 복구

- `bootstrap`이 앱 모듈을 불러와 `mountApp(root, session)`을 호출한다. 시작 실패, 잡히지 않은 실행 예외, 처리되지 않은 Promise 거부는 이 경계에서 한 번만 처리한다. 브라우저의 리소스 이벤트·예외 정보 없는 ResizeObserver 알림은 실행 예외로 취급하지 않는다.
- 앱이 획득한 자원은 즉시 `session.onDispose`에 등록한다. 초기화 중간에 실패해도 역순으로 모두 해제하며, 한 정리 함수의 실패가 나머지 정리를 막지 않는다. 치명적 오류 후에는 입력·RAF·관측자를 정리하고 오류 화면으로 교체한다. 손상 가능성이 있는 상태로 재개하거나 자동 재시도하지 않는다.
- GPU 초기화·셰이더 실행·컨텍스트 손실은 렌더러에서 CPU로 복구한다. 성공한 복구는 학습 화면을 방해하지 않으며 진단 콜백으로만 전달한다. CPU도 사용할 수 없거나 CPU 샘플링이 실패하면 실행 예외 경계가 처리한다. GPU 전용 진단은 엔진 계약에 넣지 않는다.
- 최근 30개 진단을 메모리에 보관한다. 오류 보고서는 실패 직전 조건·보기·표시 시각·렌더러·브라우저·창 크기·오류 메시지/스택과 배포 번들의 식별 경로를 담는다. 프레임마다 기록하거나 로컬 저장소에 누적하지 않으며 자동 전송하지 않는다.
- 오류 화면은 새로고침과 보고서 복사를 제공한다. 클립보드가 거부되면 선택 가능한 원문을 펼친다. 진입 번들 자체가 로드되지 않으면 `index.html`의 독립 안내와 새로고침 링크가 남는다.
- 탭/브라우저 프로세스 종료나 메인 스레드의 완전한 멈춤은 JavaScript 오류 화면으로 복구할 수 없다. 현재 원격 오류 수집·세션 재현·설정 영속 저장은 제공하지 않는다.

## 6. 격자 엔진 교체 시 확인할 계약

`WaveEngineFactory` 교체 지점은 앱 한 곳이다. 지연 위상·이력 배열·속력 비율은 공통 샘플러나 뷰의 요구가 아니다. 다만 아래 의미는 새 백엔드가 직접 충족하거나 계약을 개정해야 한다.

1. 파원별 기여와 합을 같은 프레임으로 반환한다. 합성 격자 하나만으로 두 성분을 분리할 수는 없다.
2. 경로 시작점·단면의 의미, 정상 상태 판정, 과도 포락선, 즉시 정착 동작을 명시한다.
3. 진폭 감소·반사·격자 오차를 추가하면 등진폭 상쇄와 정규화 범위를 재검토한다.
4. GPU 안에 유지되는 격자는 현재의 CPU 소유 입력 텍스처 계약으로 지원 완료된 것이 아니다. 필요하면 별도의 자원 계약을 설계한다.
5. 캐시 힌트를 제공하지 않아도 정확하게 동작하고, 제공할 때에는 동일 키의 필드 동일성을 보장한다.

격자 백엔드·엔진 선택 UI·플러그인 등록부는 현재 구현 범위가 아니다.

## 7. 교사 수업 모드 v2

`bootstrap`은 `mode=teacher`인 경우 `teacher.ts`, 그 외에는 `main.ts`를 같은 오류·세션 경계에서 시작한다. 모드 이동은 별도 세션의 시작이며 수업 안의 단계 이동과 구별한다.

두 모드는 `createExperimentController`를 사용한다. 엔진 선택은 이 제어기 한 곳이다. 수업 데이터는 엔진·시계·DOM을 보유하지 않는다. 실행본과 편집 초안은 분리하며, 무대·도구·편집기는 진행 상태를 각각 복제하지 않는다.

`LessonRunner`는 같은 예제에서 입력을 보존하고 예제 경계를 넘을 때만 현재 시각에 새 조건을 적용한다. `next()`만 출발 Cue의 명시적 재생 의도를 소비한다. 이전·직접 이동·연출 재생은 물리 시각을 되감지 않는다. 결과 직접 이동은 정상 상태가 아니면 같은 예제의 대기 단계로 간다.

렌더 순서는 시계 진행 → 목표 카메라 준비 → 표시 프레임 및 고정 해석 범위의 유효성 읽기 → 가림 결정 → 공통 프레임과 경로 샘플로 뷰 갱신이다. 카메라 범위는 엔진 생성 전에 예약한다. 해석 유효성은 입력 세대와 함께 관리한다.

`presentation/`은 지속되는 경로를 같은 크기로 회전·평행 이동한다. 장면별 자동 확대·축소는 없고 화면 크기 변경 시에만 공통 축척을 다시 계산한다. 모든 파형 소속 도형은 같은 배율을 따르며 외부 주석은 읽을 크기를 유지한다. 애니메이터는 물리 명령을 실행하지 않는다. 기존 공통 뷰의 기본 옵션을 유지하여 일반 탐색도 같은 구현을 사용한다.

자세한 파일 책임·시간·가림·저장 계약은 [교사 수업 구현](teacher-mode.md), 요구사항은 [설계 v2](teacher-mode-design-v2.md)를 따른다.
