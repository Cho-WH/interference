# 구조와 재사용 원칙

이 문서는 같은 물리 상태를 여러 시각화에서 일관되게 표현하고, 기능을 추가할 때 기존 계산·그리기·조작을 재사용하기 위한 개발 기준이다. 물리 정의는 [physics-model.md](physics-model.md), 화면과 문구는 [ux-language.md](ux-language.md), 구현 순서는 [implementation-plan.md](implementation-plan.md)를 따른다.

## 1. 기본 구성

브라우저에서 실행하는 클라이언트 앱으로 시작한다. 현재 기능에는 서버, 로그인, 데이터베이스가 필요하지 않다. 프레임워크나 렌더링 라이브러리는 구현을 시작할 때 결정한다.

초기 후보는 파동장에 Canvas 2D, 설명용 경로·점·보조선에 SVG, 조작부에 의미 있는 HTML 요소를 사용하는 구성이다. 실제 성능과 구현 복잡도에 따라 조정할 수 있으며, 물리 모듈은 렌더러와 독립된 계산 함수로 유지한다. 현재 요구는 이 구성과 명시적인 함수 호출로 해결하고, 추가 기술은 실제 성능·확장 요구가 확인될 때 판단한다.

### 책임 단위

아래는 코드가 생길 때 적용할 경계다. 각 단계에 필요한 책임을 소수의 실제 동작하는 파일로 구현하고, 재사용이나 복잡도가 생기면 나눈다.

| 위치 | 책임 | 의존 범위 |
|---|---|---|
| `src/model/` | 물리 입력 타입, 기본값, 허용 범위, 상태 변경 규칙 | 다른 앱 모듈에 의존하지 않음 |
| `src/physics/` | 파동 계산, 경로 길이, 관측점 중첩, 장·경로 샘플링 | `model` |
| `src/runtime/` | 단일 시계, 재생·일시정지, 프레임 예약 | 현재 진동수 등 필요한 값만 입력받음 |
| `src/geometry/` | 물리 좌표와 화면 좌표 변환, 공통 축척, 경로 펴기 배치 | 기본 좌표 타입; 물리 계산을 소유하지 않음 |
| `src/visual/` | 축·0선·파형 선·점·변위 막대·보조선의 재사용 가능한 그리기 | `geometry`와 전달받은 값 |
| `src/views/` | 파동장, 경로 비교, 관측점 중첩의 구성과 표시 | 전달받은 샘플, `geometry`, `visual` |
| `src/ui/` | 버튼·입력·선택·접근성, 학생용 문구 | 공개된 상태와 동작 호출부 |
| `src/app/` | 상태 보관, 입력 연결, 샘플 생성, 뷰 조립 | 위 모듈의 공개 함수 |

앱 조립부가 각 뷰에 계산 결과를 내려주고, 입력은 정해진 동작으로 되돌려 받는다. 뷰 사이의 정보 전달도 이 흐름을 따른다. 물리·시계 모듈은 계산값을 반환하고, 학생용 문구와 화면 구성은 `ui`와 `views`가 맡는다.

## 2. 상태의 단일 출처

### 물리 입력

- 두 파원의 고정된 ID, 위치, 진폭, 초기 위상과 관측점 P의 위치를 보관한다.
- 기본 수업은 같은 진동수·같은 초기 위상·같은 진폭의 두 파원을 사용한다. 조절 UI는 제품 설계에서 정한 수업 조작에 맞춰 제공한다.
- 매질의 파동 속력은 고정하고 파장을 조절한다. 속력과 파장을 입력 상태로 보관하고, 진동수는 항상 `속력 / 파장`으로 구한다.
- 물리 좌표와 거리는 내부에서 SI 단위로 통일한다. cm나 파장에 대한 비율은 출력을 표시할 때 변환하고, 계산에는 SI 단위의 원래 값을 사용한다.

### 실행·표시 상태

- 재생 여부와 공통 시계는 한 곳에서 관리한다. 경과 시간·누적 시간 위상은 시계가 소유한다.
- 선택된 요소 ID, 열려 있는 보기, 경로 펴기 진행률 등은 표시 상태로 관리한다. 표시 상태를 갱신할 때 파원·관측점의 물리 위치와 공통 시간은 유지한다.
- 경로 길이, 경로차, 도착점 변위, 합성 진폭은 물리 입력과 공통 시계에서 계산해 사용한다. 필요 시 입력에서 재생성할 수 있는 캐시로 보관한다.
- 파원 1·2의 ID와 표시 순서는 고정한다. 행·색·기호는 파원 ID에 연결하여, 관측점 이동으로 짧은 경로가 바뀌어도 같은 대응을 유지한다.

## 3. 하나의 시계와 하나의 물리 스냅샷

프레임마다 다음 순서로 갱신한다.

1. 입력으로 물리 상태 또는 표시 상태를 갱신한다.
2. 공통 시계에서 이번 프레임의 시간과 시간 위상을 한 번 얻는다.
3. 물리 상태와 시계 값으로 불변의 `PhysicsSnapshot`을 생성한다.
4. 그 스냅샷에서 파동장·두 경로·관측점의 표시 샘플을 얻는다.
5. 각 뷰는 받은 값을 화면 좌표로 바꾸어 그린다.

`WaveField`, `PathComparison`, `PointSuperposition`은 공통 시계와 물리 모듈이 생성한 같은 프레임의 값을 전달받는다. 같은 관측점을 나타내는 값은 동일한 `ProbeSample`을 사용한다. 경로 끝 샘플도 그 값과 같은 계산 경로에서 얻는다.

### 최소 계약 예시

이름은 구현에 맞게 조정할 수 있지만, 다음 값의 의미와 소유권은 유지한다. 식과 위상 부호 규약은 물리 문서 한 곳에서 정의한다.

```ts
type SourcePair<T> = readonly [T, T]; // 항상 파원 1, 파원 2 순서
type ClockFrame = Readonly<{
  timeSeconds: number;
  temporalPhase: number;
}>;
type ProbeSample = Readonly<{
  distances: SourcePair<number>;
  componentDisplacements: SourcePair<number>;
  resultantDisplacement: number;
  resultantAmplitude: number;
  signedPathDifference: number;
  phaseDifference: number;
}>;

declare function createSnapshot(model: ModelState, clock: ClockFrame): PhysicsSnapshot;
declare function samplePoint(snapshot: PhysicsSnapshot, point: Vec2): ProbeSample;
declare function sampleAlongPath(snapshot: PhysicsSnapshot, sourceId: SourceId,
                                distances: readonly number[]): readonly number[];
```

`PhysicsSnapshot`은 해당 프레임의 물리 입력·시계·관측점 샘플을 묶는다. `sampleAlongPath`에는 파원에서 출발한 SI 단위의 물리적 거리를 전달한다. 화면 픽셀과 애니메이션 진행률은 배치 계산에서만 사용한다. 장의 격자 샘플링도 같은 물리 모듈을 사용한다.

순간 변위와 합성 진폭은 서로 다른 값으로 유지한다. 합성 위상을 추가하는 단계에서는 합성 진폭이 0일 때 위상이 정의되지 않는 상태를 표현할 수 있어야 한다.

### 재생 규칙

- 사용자가 일시정지를 누르기 전까지 파동은 계속 진동한다. 보기 전환이나 경로 펴기 중에도 현재 재생 상태를 유지한다.
- 일시정지 동안 공통 시간과 시간 위상을 고정한다. 재개하면 정지 직전 값부터 다시 누적한다.
- 진동수가 바뀔 때 공통 시계의 누적 시간 위상을 유지하고 이후의 증가율을 바꾼다. 각 뷰는 공통 시계에서 전달받은 시간 위상을 사용한다.
- 느리게 보기 등의 재생 배율은 공통 시계의 진행률에 적용한다. 매질의 파동 속력·파장·진동수는 설정된 물리값을 유지한다.

## 4. 물리 샘플과 배치의 분리

### 경로 펴기

경로는 파원에서 관측점까지의 물리적 거리 좌표로 정의한다. 경로를 나란히 펴는 동안 바뀌는 것은 이 좌표를 화면에 배치하는 방법뿐이다. 같은 물리 상태와 시각에서 길이·파장·위상·관측점 샘플은 전환 전후 동일하며, 재생 중에는 공통 시계에 따라 계속 갱신한다.

- 두 경로의 시작점을 맞추고 하나의 거리 축척으로 실제 길이 비율을 표현한다.
- 반응형 화면에서도 축척은 두 경로에 함께 적용하고, 실제 경로차와 길이 비율을 유지한다.
- 짧은 경로의 끝에서 표시하는 같은 거리 보조점은 긴 경로의 동일한 물리 거리에서 샘플링한다.
- 추가 길이 강조, 보조선, 경로 펴기 전환은 `geometry`와 `visual`에서 물리 샘플의 화면 배치와 스타일을 바꾸어 구현한다.

### 관측점의 세 행

두 경로의 끝값은 수평 점선으로 오른쪽 같은 열의 성분 1·성분 2 표시점에 연결한다. 합성점은 그 아래 같은 열에 놓는다. 각 행은 자신의 0선을 가지며, 두 경로와 세 행의 변위 축척은 모두 같다.

- 경로 끝점·성분 표시점·변위 막대는 동일한 성분 변위 샘플을 각자의 화면 위치로 변환해 표시한다.
- 합성점은 두 성분의 합을 사용하고, 기본 등진폭 조건에서 최대 두 배의 진폭까지 같은 축척으로 표시할 공간을 확보한다.
- 보조선은 같은 순간의 끝값과 성분점을 직접 잇는 수평 점선으로만 그린다. 실제 파형은 각 물리 경로의 끝까지 표시한다.
- 경로의 파형은 한 시각의 공간에 따른 변위다. 오른쪽 점은 고정된 P에서 시간에 따라 변하는 변위다. 세 번째 행은 P의 합성점과 변위 막대로 구성한다.

## 5. 반복해서 사용할 구성 요소

| 구성 요소 | 공유할 책임 | 개별 뷰가 정하는 값 |
|---|---|---|
| 좌표 변환·거리 축척 | 물리 좌표↔화면 좌표, 단위 변환 경계 | 화면 영역, 공통 배율 |
| 파형 선 | 샘플을 연속 선으로 표시 | 샘플, 색·기호, 배치 |
| 축·0선 | 눈금, 기준선, 축척 적용 | 축의 의미, 범위, 행 위치 |
| 점·변위 막대 | 0선 기준 이동과 방향·크기 표시 | 변위, 공통 축척, 파원 ID |
| 선택·드래그 | 포인터·키보드 입력과 선택 상태 | 허용 동작, 이동 대상과 범위 |
| 재생 조작부 | 공통 재생 상태 표시와 변경 | 조작부를 놓을 위치 |

재사용은 좌표·값·스타일을 입력받는 작은 함수나 컴포넌트로 시작한다. 학생에게 보이는 문구는 `ui`의 문구 정의에서 가져온다. 학생 UI에는 물리 개념과 조작에 필요한 표현만 사용하고, 내부 타입명·렌더러·계산 절차의 설명은 개발 문서와 코드에 둔다.

### 기능을 추가할 때

1. 먼저 기존 물리 값, 샘플링, 그리기, 입력 중 재사용할 것을 찾는다.
2. 새 물리량이 필요하면 `physics`의 공개 결과를 확장하고, 필요한 뷰에 그 결과를 전달한다.
3. 새로운 표현만 필요하면 기존 스냅샷과 그리기 요소를 조합한다. 예를 들어 P의 시간 기록은 공통 시계의 시각과 같은 관측점 샘플을 함께 기록한다.
4. 새로운 조작은 중앙 상태 변경 규칙을 거친다. 변경된 상태를 앱 조립부가 관련 뷰에 전달한다.
5. 실제로 반복되는 책임이 확인될 때 공통 요소로 추출한다. 확장점과 설정은 현재 구현하는 기능의 구체적인 요구를 기준으로 추가한다.

## 6. 변경에 맞춘 검증

검증 범위는 변경된 책임과 직접 영향을 받는 소비처로 정한다. 상세 완료 기준은 [implementation-plan.md](implementation-plan.md)를 따른다.

| 변경 | 확인할 범위 |
|---|---|
| 물리식·샘플링·공통 시계 | 바뀐 계산 사례와 이를 사용하는 파동장·경로·관측점의 값·시각 동기화 |
| 경로 배치·축척 | 두 경로의 시작점·거리 축척·같은 거리 표시·끝점 대응 및 해당 화면 크기 |
| 공통 점·막대·입력 요소 | 그 요소를 사용하는 화면의 영향을 받는 동작 |
| 문구·버튼 위치 | 바뀐 문구의 정확성·이해 가능성 또는 해당 조작 흐름 |
| 설계 문서 | 변경된 요구의 일관성과 관련 문서 연결 |

먼저 변경으로 생길 수 있는 구체적인 오류를 정하고, 이를 확인할 최소한의 계산 사례·조작·화면 확인을 선택한다. 전체 테스트나 빌드는 변경의 직접 영향이 전체에 걸칠 때 선택한다. 자동 검증은 실제 계산 관계나 사용자 동작의 회귀 오류를 잡는 데 필요할 때 추가한다. 관련 오류를 충분히 확인하면 검증을 마치고, 실제 확인한 범위를 완료 보고에 짧게 적는다.
