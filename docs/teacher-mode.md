# 교사 수업 모드 구현

이 구현은 [교사 수업 모드 설계 v2](teacher-mode-design-v2.md)의 세 단계 범위를 따른다. `?mode=teacher`로 진입한다. 물리 엔진은 기존 지연 위상 엔진이며, 수업 진행·표현·편집을 별도 모듈로 구성했다.

## 기본 수업

기본 구성 개정 4는 8장면, 26개의 수동 정지 지점을 제공한다. 다음 버튼은 시간을 자동으로 넘기는 슬라이드 재생기가 아니다. 각 공개 후 교사가 기다리고 다음 행동을 선택한다.

| 장면 | 관찰과 공개 | 예제 |
| --- | --- | --- |
| 1 전체 현상 | 필드 → 고정 P를 0점으로 한 합성 변위 | A |
| 2 두 경로 | 파원 1 → 파원 2 → 함께 | A |
| 3 펼치기 | 같은 순간에 멈추고 제자리 회전 → 정지 | A |
| 4 비교 | 공통 확대 → 같은 거리 → 추가 경로 → 눈금 → 수치 | A |
| 5 더하기 | 끝점 → 명시적 재생 → 합 공개 | A |
| 6 다른 P | 현재 P로 공간 복귀 → B로 이동 → 제자리 펼침 → 확대·거리로 예측 → 성분 → 합 | A → B |
| 7 다른 파장 | A에서 예측 → C의 도착 대기 → 성분 → 합 | A → C |
| 8 정리 | 같은 공간으로 접기 → 조건식 → 자유 탐구 | C |

A는 거리 45/52.5cm, λ=15cm인 상쇄 예제다. B는 45/60cm, λ=15cm인 보강 예제다. C는 A와 같은 P·파원 간격에 λ=7.5cm를 적용한 보강 예제다. 모든 계산은 기존 엔진 결과로 확인한다.

장면 6의 첫 공간 복귀는 A의 현재 입력을 유지하므로 교사가 옮긴 P로 돌아간다. `조건 B로 · P 옮기기`에서 B를 한 번 적용한다. 두 경로 위 파형은 이동·펼침·예측 내내 유지하고 간섭무늬와 합성 진동만 가린다. 이동 후, 펼침 후, 예측 후 각각 교사의 다음 조작을 기다린다. 도착 성분을 따로 비교한 뒤 합을 공개한다. B의 예측과 확인에는 같은 B의 입력을 사용한다.

## 실행과 시간

- `ExperimentController` 한 개가 엔진과 물리 시계를 소유한다. `applyPreset()`은 P·λ·파원 간격을 같은 물리 시각에 적용하고, 변경된 방출 조건은 전파된다.
- `LessonRunner`는 분리된 실행본, 현재 Cue, 예제 진입 번호, 화면 가림, 임시 표시 선택, 자유 조작의 복귀 지점을 소유한다.
- 같은 예제의 다음·이전·직접 이동은 현재 조건을 유지한다. 다른 예제에 들어갈 때만 그 예제의 입력을 현재 시각에 적용한다. 이전 이동도 시간을 되감지 않는다.
- 출발 Cue의 명시적 `clockIntent`는 다음으로 진행할 때만 적용한다. `멈추고 펼치기`와 `재생하며 관찰` 외에는 재생 상태를 보존한다.
- 결과로 직접 이동해도 아직 정상 상태가 아니면 안전한 대기 단계로 간다. 도착 후 자동 공개나 예약된 다음 클릭은 없다.
- 정지 중 조건이 바뀌면 “재생하면 새로운 조건이 도착합니다”를 표시한다. `변화 과정 생략`은 현재 시각에서 정착시키며, `예제 다시 시작`·`수업 처음부터`는 명시적인 새 실험이다.
- 자유 조작에서 돌아올 때 현재 조건 유지가 기본이다. 조건 복원은 별도 선택이며 현재 시각에서 적용한다. P·파장·파원 간격을 바꾸어도 단계별 질문은 이어진다. 기본 예제의 특정 수치나 보강·상쇄 결과를 전제로 한 질문과 교사 메모만 해당 단계의 관찰·예측·설명 목적을 유지한 문장으로 바꾼다. 교사가 직접 작성한 질문과 메모는 각각 보존한다. 조건 변경 여부는 상태 표시줄에서 별도로 알린다.

## 표현과 공개

`Stage`는 Canvas 필드, SVG 경로·진동·대응 표식, HTML 질문을 계속 유지한다. 장면별로 엔진이나 Canvas를 복제하지 않는다. 모든 뷰는 같은 `WaveFrame`과 경로 샘플을 소비한다. 공간 카메라를 준비한 뒤 그 범위를 읽는다.

공간의 합성 변위 막대는 P의 중심을 0점으로 삼고 그 위치에서 수직으로 표시한다. P의 원과 손잡이는 고정하고 보라색 점과 막대만 현재 합성 변위를 따른다. 표시에는 포인터 입력을 받지 않아 P의 드래그·누르기 조작을 유지한다. 펼친 끝값 비교의 합성점 배치는 그대로다.

`move-probe`는 1200ms 동안 표시 관측점을 보간한다. `readBundle(bounds, observationProbe)`로 기존 엔진에서 그 위치를 읽어 P·거리·경로 끝·위상을 같은 프레임에 맞춘다. 저장된 B 조건과 물리 시계·전파 이력은 연출 때문에 재설정하지 않는다. 물리 시간이 정지해도 P 이동 연출은 완료되며, 동작 감소·전환 완료·다시 보기는 기존 연출기를 사용한다.

`layout.ts`는 화면 안전 영역, 최대 진폭, 실제 경로 길이로 배치를 계산한다. 파원 중심의 회전 동안 경로 길이·파장·변위를 보존한다. 확대는 두 경로와 변위에 같은 배율을 적용하고, 행 간격은 별도 평행 이동한다. 물리 입력을 바꿀 때마다 자동 확대하지 않는다. 잘린 경로에는 절단 표시와 `전체 경로`를 제공한다.

폭 700px 미만의 모바일 무대에서는 장면별 확대를 하지 않는다. 공간 보기·제자리 펼침·거리 분석·도착점 비교·복귀 모두 최초 거리·변위 축척과 파형·점·선의 크기를 유지하고, 위치와 행 간격만 조정한다. 같은 화면 크기에서 A/B/C 전환과 역방향·동작 감소도 이 규칙을 따른다. 화면 자체를 회전하거나 크기를 바꿀 때는 새 화면의 공통 축척을 계산한다.

`recipes.ts`와 `animator.ts`는 물리 계산이 없는 연출 시간선이다. 펼치기 1360ms, 공통 확대·끝점 집중 780ms, 단순 공개 220ms를 기본으로 느림/보통/빠름을 적용한다. 배경 퇴장과 회전은 겹치고, 접을 때는 공간 복귀 후 배경이 나타난다. 전환 중 다음은 전환만 완성한다. 역전은 현재 자세에서 출발한다. 숨김 탭에서는 두 시계를 보류한다.

`reveal-policy.ts`는 교사 임시 선택보다 우선하는 가림을 적용한다. 거리 예측에서는 필드·파형·도착 성분·합·비율을 가리고 거리 기준선과 λ를 남긴다. 합 예측에서는 성분을 보여 주되 필드·국소 합·합성점을 가린다. 화면 전환의 이전 배경도 예측 단계에 남지 않는다.

표시 범위의 정상 상태와 해석 범위의 정상 상태는 다르다. `readBundle()`은 동일 시각에 현재 카메라의 프레임과 고정 실험 범위(1.2×0.72m)의 해석 유효성을 읽는다. 입력 세대가 바뀌면 유효성을 다시 읽으며, 카메라 확대나 정지 버튼만으로 정상 상태를 선언하지 않는다.

연출 감소에서는 넓은 화면에 같은 축척의 공간/펼침 그림을 함께 보여 주며 좁은 화면은 앞뒤 보기로 전환한다. HTML 질문·버튼은 축척과 독립적으로 읽을 크기를 유지한다. WebGL2 미지원 시 기존 CPU 필드와 같은 SVG 경로를 사용한다.

## 조작과 준비

진행 바에는 장면 개요, 이전, 물리 재생, 다음 행동, 도구를 둔다. 도구에서 전체 화면, 가림, 포인터, 연출 감소, 연출 다시 보기, 자유 조작, 복원·정착·초기화, P·파장·간격, 물리 배속·연출 속도, 표시 선택, 교사 메모, 편집을 연다. 교사 메모는 현재 화면에 투사되는 내용임을 표시한다.

키보드: 오른쪽/왼쪽·PageDown/PageUp은 단계 이동, K는 재생, F는 전체 화면, B는 가림, O는 개요다. 입력란·P 손잡이·대화상자는 수업 단축키를 가로채지 않는다. Space는 일반 무대에서 다음으로 진행하고, 버튼에 초점이 있으면 그 버튼의 기본 동작을 따른다.

편집기는 카드 목록·실제 무대 미리보기·설정의 세 영역이다. 질문·메모·투사 여부, 공개 정보, 허용 조작, 예제 입력, 구도, 속도, 보조 카드 이동·묶기, 장면 이동을 제공한다. 보호된 정지와 선행 조건을 위반하는 이동은 적용하지 않고 원인을 표시한다. 질문 편집·이동·묶기·예제 저장은 취소할 수 있다.

미리보기는 정상 상태의 새 예제임을 명시한다. `이 단계부터 리허설`은 초안의 입력 조건으로 시작하며, `리허설 끝내기`는 선택 카드로 돌아온다. 실험 입력은 자동 저장하지 않는다. `현재 조건을 예제로 저장`으로 명시적으로 반영한다. `이 구성으로 시작`에서 초안을 새 실행본으로 확정한다.

## 저장 계약

`LessonSpec`은 지원 버전·엔진 계약·모델 프로필·입력 조건·선언적인 Cue만 저장한다. 함수, DOM, 시계, 프레임, 전파 이력은 넣지 않는다. JSON은 500KB 이내, 지원 키·ID·수치 범위·예제 참조·대기 선행 조건·보호된 가림·A/C의 같은 P와 절반 파장 조건을 검사한다. 잘못된 가져오기는 기존 초안과 저장본을 보존한다.

브라우저에는 수업과 마지막 단계·입력 조건을 별도로 저장한다. 재개는 “저장한 조건에서 새 실험 시작”으로 안내하며 과거 전파 이력 복원을 주장하지 않는다. 질문에 HTML을 넣어도 일반 텍스트로 표시한다.

이전에 저장한 교사 구성은 자동으로 덮어쓰지 않는다. 새 기본 흐름은 편집기의 `기본 구성`에서 선택해 저장한다. 개정 2의 수업 파일도 계속 읽을 수 있다.

## 파일과 검증

| 책임 | 파일 |
| --- | --- |
| 공통 물리 명령·프레임 | `src/app/experiment-controller.ts` |
| 앱 결합·수명·미리보기 | `src/app/teacher.ts` |
| 수업 데이터·진행 | `src/lesson/types.ts`, `default-lesson.ts`, `runner.ts` |
| 가림·문구·유효성 | `reveal-policy.ts`, `teaching-copy.ts`, `validation.ts` |
| 초안·저장 | `editor-model.ts`, `storage.ts` |
| 무대·배치·연출 | `src/presentation/` |
| 진행 도구·편집 UI | `src/ui/presenter-controls.ts`, `lesson-editor.ts` |

단위 검사는 물리 시각 유지, 예제 진입, 직접 이동 대기, 가림과 입력 잠금, 자유 조작 복귀, 스키마와 편집 보호, 확대·역전·중단, 실제 A/B/C의 진동을 다룬다. 브라우저 검사는 실제 진행·편집·반응형·CPU 대체·표시 두께와 프레임 일치를 다룬다. 검사 실행 범위는 완료 보고에 구별해 기록한다.

별도 교사 창, 학생 응답 수집, LMS 연동, 과거 이력의 직렬화는 이 버전의 범위 밖이다. 실제 교실 투사, 학습 효과, Safari·실제 모바일 기기는 별도 확인이 필요하다.
